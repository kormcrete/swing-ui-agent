Order Desk comes with IntelliJ run configurations, so you can start the app with the agent, run its UI tests, and record
a new test without setting anything up. No coding agent is needed: you record the test with the palette in the app and
export it into the project yourself.

You will learn how to:

- start Order Desk with the agent from a run configuration;
- run the UI tests from the IDE;
- record a new test with the palette and export it as a JUnit class;
- run the new test and debug it.

## Before you start

- IntelliJ IDEA with a JDK 8 or later.
- swing-ui-agent installed in your local Maven repository, as in [Installation](/swing-ui-agent/start/install/#1-build-and-install-it).
- Order Desk cloned: `git clone https://github.com/kormcrete/swing-order-desk-demo.git`. Open the folder in IntelliJ
  (**File ▸ Open**) and let it import the Maven project.

## The run configurations

They are in the project's `.run/` folder, so IntelliJ lists them as soon as the project is open:

| Run configuration | What it does |
| --- | --- |
| **Order Desk** | Starts the app with the agent on port 8770 and the palette for recording (`palette=off` leaves it out). |
| **UI tests** | Runs every `@UiTest` class (JUnit tag `ui`) against the running app. |
| **All tests** | Runs the unit tests (tag `!ui`). They need no app. |

Before the app starts, the app configuration copies the agent jar from your Maven repository to
`target/swing-ui-agent-agent.jar`, so a fresh clone works on the first run. The tests find the agent through
`src/test/resources/junit-platform.properties` (`swingui.agents=127.0.0.1:8770`), so the gutter icons work too. The
same file runs the UI test classes by name, in one order everywhere, as they share one app.

Only one Order Desk can listen on port 8770 at a time: stop a running one before you start another.

## 1. Start the app and run its UI tests

1. Choose **Order Desk** in the run configuration list and press **Run**. Order Desk opens on its Orders tab.
2. Run **UI tests**. To run one test class, open it, for example
   `src/test/java/io/github/kormcrete/orderdesk/PlaceOrderUiIT.java`, and click the gutter icon next to the class.

**UI tests** runs Order Desk's two tests, and you can watch them in the app: `CartTotalsUiIT` fills Ada Shop Ltd's
cart, checks its totals and discards it, then `PlaceOrderUiIT` takes an order for Ada through checkout. It saves a
screenshot after each step in `target/ui-screenshots/PlaceOrderUiIT/`. See
[PlaceOrderUiIT, step by step](/swing-ui-agent/demo/recorded-test/) for what each step does.

<RunDemo />

- **No app running:** the tests fail in under a second with "no swing-ui-agent on 127.0.0.1:8770". Start
  **Order Desk** and run them again.
- **A failure:** the evidence is in `target/ui-failures/<Class>/<method>/`: what was expected, what the app showed,
  and a screenshot. See [Run the tests](/swing-ui-agent/start/run/).
- **Many runs:** each run of `PlaceOrderUiIT` places a real order for Ada, who has a credit limit. Restart the app before about 40 runs.

## 2. Record a new test

Run **Order Desk** (or use the one that is already running). The palette appears at the bottom right of the window.

1. Press **● Record**.
2. Make the first step one that gets the app to the starting screen from anywhere, such as **File ▸ New order**
   (see [Reset and the starting screen](/swing-ui-agent/guides/reset/)).
3. Use the app. Each click, selection and committed text field becomes a step.
4. Press **Check**, click an element, and choose a check from the menu. Press **Record** to go on recording.
5. Press **Steps** to see the recording. Replay it, redo from a step, or delete one until the recording is right.
6. Press **Done**.

A recording can also be checks only, such as "ORD-1639 is Placed": the test then only asserts. More on each step in
[Record a test by showing it](/swing-ui-agent/start/show/).

## 3. Export it as a JUnit class

After **Done** the palette offers **Export…**:

1. Press **Export…**.
2. Choose **Java test** (the panel opens on **Recorded test**) and enter the class name, ending in `UiIT`, for
   example `CancelOrderUiIT`. The package is already filled in with the app's own package,
   `io.github.kormcrete.orderdesk`.
3. Press **Export**.

The palette says where the file went: `src/test/java/io/github/kormcrete/orderdesk/CancelOrderUiIT.java`. The
recording stays, and an existing file is never overwritten (see
[Record a test by showing it](/swing-ui-agent/start/show/#5-press-done-then-export)).

You can also export from IntelliJ's terminal, or let a coding agent do it:

```sh
java -jar target/swing-ui-agent-agent.jar --port 8770 \
     export_test '{"class":"CancelOrderUiIT","package":"io.github.kormcrete.orderdesk"}'
```

## 4. Run the new test, then commit it

1. Open the new class. IntelliJ shows it in the project once it notices the file.
2. Read it as you would any change. Every step is one line, and each check is an `assertThat`.
3. Put the app on another screen, for example open an order's tab, and run the test from the gutter. It has to get
   to its own starting screen and pass from there.
4. Commit it with the project. **UI tests** and `mvn -B -Pui verify` now run it with the others.

## Debug a test

- **The test:** set a breakpoint in the test class and run it with **Debug**. The app waits while the test is
  stopped.
- **The app:** start **Order Desk** with **Debug** and set breakpoints in the app's code. The test drives the app
  into them.
- **What the agent sees:** run `java -jar target/swing-ui-agent-agent.jar --port 8770 snapshot` in the terminal for
  the element tree the test works with.
