## Try it in two minutes

Download Order Desk, a small Swing order-entry app with the agent built in. Nothing to build.

1. **Download** it for
   [Mac with Apple Silicon](https://github.com/kormcrete/swing-order-desk-demo/releases/latest/download/kormcrete-order-desk-macos-arm64.dmg),
   [Mac with Intel](https://github.com/kormcrete/swing-order-desk-demo/releases/latest/download/kormcrete-order-desk-macos-x64.dmg),
   [Windows](https://github.com/kormcrete/swing-order-desk-demo/releases/latest/download/kormcrete-order-desk-windows-x64.zip)
   or [Linux and any Java 8+](https://github.com/kormcrete/swing-order-desk-demo/releases/latest/download/kormcrete-order-desk-java.zip),
   and open it. The first launch takes one extra step:
   [first launch](/swing-ui-agent/demo/tour/#download-and-run-it).
2. **Run a recorded test:** in the bar at the bottom of the window, press **Load recorded test…**, pick `place-order`
   and press **▶ Run**. Order Desk comes with three; the app takes the order by itself and checks every total.
3. **Connect your agent** while the app runs:

   ```sh
   claude mcp add --transport http order-desk http://127.0.0.1:8770/mcp
   ```

4. **Ask it:** *"Create a new order for Ada Shop Ltd with 3 packs of A4 paper and 10 black gel pens, check out, and
   tell me the order number."* Ada Shop Ltd pays by invoice, so if it asks for a PO number, give it any.
5. **Ask again**, for another customer or other products. The first time takes longer: the agent reads the screens
   and learns the order form. Now it knows them and can send all the steps in one `batch` call: the whole order runs
   in about half a second.

:::tip[Let it remember]
What the agent learns lasts only for the conversation. Ask it to save what it learned about the app (the screens,
the field names, that invoice customers need a PO number) to its memory or project notes, such as your
`CLAUDE.md`, so the next session starts fast. To keep the steps themselves, ask it to
[save them as a recorded test](/swing-ui-agent/start/record-together/).
:::

Then [take the tour](/swing-ui-agent/demo/tour/), or see how the same steps
[become a recorded test](/swing-ui-agent/start/record-together/).

## Two ways to record a test

Either way the agent does the work, and the result is a **recorded test**: a JSON file in `uitest/` with a numbered
sentence per step, nothing to compile.

<CardGrid>
	<Card title="Show it yourself" icon="pencil">
		Start the app with the agent (the palette is on by default), press **● Record** in the palette and use the app.
		**Check** adds checks of what you see, **Steps** replays, fixes and names them. After **Done**, **Export…** saves
		the recorded test. **Load recorded test…** opens one again to run it step by step and save changes back.

		Your agent can help: ask it to add steps while you record. When it is not sure what you mean, it boxes what it
		found, and you confirm the one you mean.

		[Record a test by showing it](/swing-ui-agent/start/show/)
	</Card>
	<Card title="Tell the agent" icon="seti:shell">
		Say the test in words. The agent drives the live app, checks each step, names the steps in plain words and saves
		the recorded test. You can watch the steps appear in the palette and undo what you do not like.

		```sh wrap
		$UI session '{"op":"reset"}'
		$UI menu '{"path":["File","New order"]}'
		$UI type '{"target":{"name":"Customer"},"text":"Ada"}'
		$UI export_recorded_test '{"name":"place-order"}'
		```

		[Record together with your agent](/swing-ui-agent/start/record-together/)
	</Card>
</CardGrid>

## A recorded test is a file you can read

- **Exact values, what is on screen.** It checks what a person sees, such as the cart's **Total** reading `€31.32`.
  The data is yours to arrange: the test creates what it checks, or uses data you know exists.
- **One numbering.** Steps and checks are numbered the same in the palette, the reports and the file: step `7`, its
  check `7.2`.
- **Runs anywhere.** Load it in the palette and press **▶ Run**, let the agent run it, or run the whole folder from
  Maven and CI. [Run and edit a recorded test](/swing-ui-agent/start/recorded-tests/)

When a test needs more, or more technical checks (values that change from run to run, a database, files, logs, anything
the test's JVM can reach), the agent can write a JUnit 5 `@UiTest` class instead. The two kinds do not mix.
[Recorded tests or Java tests](/swing-ui-agent/start/choose-test-kind/)

## Built for real Swing apps

- **Waits for the app, not a timer.** Every action lets the app settle before it returns, and checks retry until they
  hold. [Waiting](/swing-ui-agent/guides/waiting/)
- **Finds what a user sees.** Labels, button text, column headers and cell text, not pixel positions.
  [Targets and locators](/swing-ui-agent/guides/targets/)
- **Leaves your mouse alone.** Input goes into the app's event queue, so it works with other windows in front.
- **One long-running app, isolated tests.** Each test gets to its own starting screen, and a lease keeps two clients
  out of each other's way. [Reset and the starting screen](/swing-ui-agent/guides/reset/)

## Built for coding agents

- **A tree, not a screenshot.** `snapshot` returns the windows as an element tree, scoped as narrowly as the agent
  asks. `screenshot` is there when a picture helps.
- **Errors that say what exists.** A locator that misses comes back with the near misses, so the next try is right.
- **Records with you.** The agent can start a recording, add steps and checks, and name them in sentences, while you
  watch the palette and undo what you do not like. [Record together](/swing-ui-agent/start/record-together/)
- **Skills included.** Three agent skills teach the drive, target and record workflow.
  [Skills](/swing-ui-agent/agents/skills/)
- **Safe by default.** Loopback only, and no tool runs commands or evaluates code.
  [Security](/swing-ui-agent/agents/security/)

## See it run

Order Desk is a small Swing order desk made to be driven: tabs, sortable tables, a tree, popup menus, a checkout
wizard with rules, a background task and a file chooser. Its tests were recorded by an agent and run in CI. The one
playing above is Order Desk's recorded test `uitest/cart-totals.json`: it fills Ada's cart and checks its totals.
`uitest/place-order.json` takes an order through checkout, and `PlaceOrderUiIT`, a Java test, does the same and reads
the new order's number.
